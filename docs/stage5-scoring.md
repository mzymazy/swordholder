# 第五阶段复评：差异度到底能提到几分

公式与 S1–S4 完全一致（权重是项目自定义口径，可复算、不可外部验证）：

```
composite = 20 × (0.20×问题真实性 + 0.25×差异度 + 0.25×证据强度 + 0.15×交付成熟度 + 0.15×变现清晰度)
```

S4 的基线分项（以 `docs/stage4-release-and-integration.md` 与 `CHANGELOG.md` 为准）是
**3.40 / 3.10 / 4.30 / 3.30 / 3.00 = 69.5**。这里要先纠正一处口径错误：本轮任务描述里把"差异度
2.6"当成最低项，但仓库内登记值是 **3.10**，S4 真正的最低项是**变现 3.00**。
按任务要求本轮仍补差异度，同时顺带推进交付；变现不动，因为没人来买这件事不能靠写文档解决。

## 1. 复评结果

| 维度 | S4 | S5 | Δ | 依据（全部可复算） |
|---|---|---|---|---|
| 问题真实性 | 3.40 | 3.40 | 0 | 定位未变。"给 AI 结论定责"这个问题的存在性 S5 既没有证伪也没有加强 |
| 差异度 | 3.10 | **3.60** | **+0.50** | 首次做逐项正面对比：3 条宣称里 1 条立住且可量化（步级定位 9 类 7/7、50 位置 50/50；单凭证 N=50 体积 25.9× 更小、验证 7.3× 更快、签名数 50× 更少）、1 条只对部分对手成立、1 条不成立（离线验签）。仍无第三方复现、无 Sigstore 同机数据 |
| 证据强度 | 4.30 | **4.50** | **+0.20** | 新增一条命令复算的 `evidence/stage5_diff/bench.json`、带 URL 与原文摘录的 `competitor_facts.json`、6 个把结论钉死的回归用例（全库 330 passed）、`twine check` 对 0.7.2 两件发行物 PASSED |
| 交付成熟度 | 3.30 | **3.55** | **+0.25** | 新增 tag 触发的 `release.yml`（构建→验收→OIDC 发布）；wheel 重建为 0.7.2 且元数据校验通过。但**发布从未真正执行**（见 N-S5-01/02），仍无外部使用者 |
| 变现清晰度 | 3.00 | 3.00 | 0 | 无付费意向书、无试点、无客户、无成交。S5 没有任何一条改动能让买家多付钱 |
| **composite** | **69.5** | **73.8** | **+4.3** | 拆解：差异度 +2.50、证据强度 +1.00、交付 +0.75 |

复算：

```
20 × (0.20×3.40 + 0.25×3.60 + 0.25×4.50 + 0.15×3.55 + 0.15×3.00)
= 20 × (0.680 + 0.900 + 1.125 + 0.5325 + 0.450)
= 20 × 3.6875 = 73.75 ≈ 73.8
```

## 2. 差异度这 0.50 是怎么来的（以及为什么没给更多）

加分只来自"同一件事两人同口径测"的三段结果，来自 `docs/stage5-head-to-head.md`：

| 宣称 | 判定 | 硬数字 |
|---|---|---|
| 步级定位 | **立住（唯一可量化护城河）** | 9 类篡改 9/9 检出、需步号的 7 例 7/7 精确；50 步全位置 50/50 精确到步号 |
| 单凭证覆盖整条轨迹 | **立住（数量级差）** | N=50：955 B vs 24,750 B（25.9×）、验证 0.99 ms vs 7.22 ms（7.3×）、签名 1 次 vs 50 次 |
| 无外部日志/CA 依赖 | **只对一半对手成立** | 验签输入 2 文件 970 B；对 Sigstore keyless / SCITT 成立，对 in-toto / JACS 不成立 |
| 离线验签 | **不构成差异** | 30/30 VALID、网络调用 0 次，但对手同样声称可离线 |

没给到 3.8 以上的原因写在这里，不藏在脚注里：

1. **没有第三方独立复现**。所有数字来自同一台机器、同一个进程、同一份自建基准脚本。
2. **Sigstore 一侧没有同机数据**——`cosign` 未安装，bundle 体积与 inclusion proof 校验耗时全部缺失。
3. **in-toto 只测到 link 级验签**，用户真正会跑的 `in_toto_verify`（layout + 制品规则）没测，7.3× 不能外推。
4. **对手的能力陈述多来自自述文档**（JACS 对比页自己声明"可含未发布变更"），用别人的勾选去证明"他们没有"，证据等级天然低一档。
5. **N=1 时我们更慢**（0.83 ms vs 0.15 ms），交叉点 N≈6；单步场景这条差异是负的。

## 3. 负结果登记（N-S5-01 … N-S5-12）

| 编号 | 做不到 / 未验证的事 | 事实与原因 |
|---|---|---|
| N-S5-01 | PyPI 未发布 | `https://pypi.org/pypi/swordholder/json` 返回 404 NOT_FOUND，包名仍可用但从未上传 |
| N-S5-02 | CI 发布路径从未执行 | `release.yml` 只在推 `v*` tag 时触发；推 tag 是对外发布动作，且仓库无 `PYPI_API_TOKEN`、PyPI 侧 Trusted Publisher 未登记，本轮**没有推送任何 tag**，所以该 workflow 一次都没跑过 |
| N-S5-03 | `twine check` 不等于能上传 | 本机 `twine 7.0.0` 对 whl/sdist 均 PASSED（元数据可渲染），但环境内无 token、无 `~/.pypirc`、keyring 无凭据，上传这一步不具备条件，也未尝试 |
| N-S5-04 | Sigstore/cosign 无同机测量 | 未安装客户端，验签耗时、bundle 体积、inclusion proof 校验全部"未测" |
| N-S5-05 | in-toto layout 级未测 | 需构造完整 layout + 步骤命令 + 制品，本轮只做每步 Link 的签名/验签对照 |
| N-S5-06 | SCITT 零量化 | RFC 9943 只有规范（TS / Receipt / Signed Statement），无可运行实现，无法做任何计分对比 |
| N-S5-07 | JACS 零量化 | 只有能力勾选页，无数字、无实现可跑；"离线 / 无中央设施"对 JACS **不成立**（其自述同为 Yes），该差异面因此归零 |
| N-S5-08 | 无第三方复现 | 全部数字为单机单进程自测，无外部独立执行记录 |
| N-S5-09 | 单步场景劣势 | N=1 验证 0.83 ms vs in-toto 0.15 ms，交叉点 N≈6；称"总是更快"即为不实 |
| N-S5-10 | 新用例覆盖面有限 | 6 个新用例只钉住三件事（不存在的凭证走结构化拒绝、导入期零网络模块、步级定位与截断），未覆盖 locale / 时区 / 文件系统差异 |
| N-S5-11 | LLM 路径网络行为无回归 | `rules.py` 改为函数内惰性导入后，"首次调用 `llm_enrich` 才导入 urllib"这一行为没有专门用例守住 |
| N-S5-12 | 无覆盖率数据 | 330 passed 只说明用例通过，没有 coverage 报告；新增用例对总体覆盖率的贡献无法量化 |

## 4. 这一轮的净收获（去掉修辞）

- **能写进对外材料的只有一句**：一条凭证覆盖整条动作轨迹，且能指到第几步断的；N=50 时体积 25.9×、验证 7.3×、签名 50×。
- **必须从材料里撤下的**："我们支持离线验签"（对手也支持）、"我们不依赖外部设施"（对 JACS 不成立）。
- **顺手修掉的两个真缺陷**（都是被实测逼出来的，不是设计时想到的）：`rules.py` 顶层 `import urllib.request` 让导入期就加载网络栈；`tool_verify_seal` 在凭证文件不存在时返回非 `verdict` 形态，等于最该 fail-closed 的路径绕过了统一契约。
- **分数涨了 4.3，但没有一分来自"更能发现问题"**：差异度涨的是"把已有差异测出来并写清边界"，交付涨的是"CI 蓝图与元数据校验"，两者都不是产品能力增长。变现一分没动——**没有人来买这件事，仍然是最低项，而且没有任何技术工作能补上它。**
